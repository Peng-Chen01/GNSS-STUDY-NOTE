## 1. GPS navigation message
Parameters need to know
GPS  transmit rate = 50 bit/s
bits duration = 20ms

30 bits = 1 word              600ms
10 word = 1 subframe     6s
5 subframe = 1 page       30s
25 pages = 12.5 mins      

GPS navigation message
Containing the information related to satellites position (ephemeris) and other information useful at receiver level(ionospheric models parameter)

First two words of each subframes are Telemetry word(TLM) and Hand over word(HOW):
1. TLM used to synchronise the navigation message
2. HOW contain the truncated version of the TOW(1-17), system state(18,19), subframe identification number(20-22), parity bits(23-30)

Why HOW use truncated version, since the gps TOW need 19 bits to record, but HOW only has 17 bits to record, therefore, z-count = TOW_how * 4
## 2. GPS time scale
GPS time is referenced to UTC (Coordinated-Universal-Time), started at 1980.1.6 00:00:00 UTC .
GPS-time counted in terms of 1.5 seconds (Z-count)

Normally one week = $7*24*3600$ = 604800 seconds, but $2^{19}=524288$, 19 bits is not enough to record one week second, if use z-count one week has 403120 seconds, 19bits could handle it. 

Z-count reduced the memory size. MSB(most significant bits) 10 bits used for gps week, every week increase 1, LSB(Least significant bits) used for TOW, every time reach 403120, it will clear and restart from 1.

## 3. PVT solution
PVT solution is the result of  iteration:
Pseudo range calculation
position and time
corrections

solution1:
$\rho_i = c(t_{Ri}^{(u)}-t_{Ti}^{(s)})$   pseudo range of i-th satellite is the light speed multiply the receiver time - satellite transmit time. 
$\rho_i = c(t_{Ri}^{(u)}-t_{sub})$ = $c(t_{Ri}^{(s)}-\Delta b - t_{sub})$  

Dynamic scenario must be taken into account, satellite move and user clock drift make measure un consistent, this solution accuracy is limited, $\Delta b$ is changes in time, 4 satellite $\Delta b$ is not same.

solution2:
between two subframe there is a 6 seconds interval that without time information, the receiver has to track the gps time

how to do it?
Accumulators $X_i(n)$ number of chips $P_i{(n)}$ number of NCO(Numerically Control Oscillator) steps control the chip fraction part.

$t_{Ri}=1.5Z_i(n)+X_i(n)T_c+P_i(n)\frac{T_c}{2^{32}}$  where $T_c$ is the chip time

solution 3: receiver schedule a measurement time, this approach can make the $\Delta b$ are same.
